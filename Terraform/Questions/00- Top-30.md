# Top 30 Terraform Interview Questions (2–4 Years Experience) – Answers

---

## 1. What is Terraform and how does it work?

Terraform is an open-source Infrastructure as Code (IaC) tool used to provision and manage infrastructure. It uses declarative configuration files (.tf) to define resources. Terraform creates an execution plan and applies it to reach the desired state.

---

## 2. What is Infrastructure as Code (IaC)?

IaC is the practice of managing infrastructure using code instead of manual processes. It ensures consistency, versioning, and automation.

---

## 3. What are Terraform providers?

Providers are plugins that allow Terraform to interact with cloud platforms like AWS, Azure, and GCP. Example: `aws`, `azurerm`.

---

## 4. What is a Terraform resource?

A resource represents a component of infrastructure (e.g., EC2 instance, S3 bucket).

---

## 5. Difference between `terraform init`, `plan`, and `apply`?

* **init** → Initializes project and downloads providers
* **plan** → Shows execution changes
* **apply** → Applies the changes

---

## 6. What is Terraform state file?

It is a `.tfstate` file that stores the current state of infrastructure.

---

## 7. Why is Terraform state important?

* Tracks resource mapping
* Enables updates instead of recreation
* Stores metadata and dependencies

---

## 8. What is remote state in Terraform?

Remote state stores the state file in a shared location like S3, enabling team collaboration.

---

## 9. What are Terraform modules?

Modules are reusable blocks of Terraform code used to organize and simplify configurations.

---

## 10. How do you create reusable modules?

* Create a folder with `.tf` files
* Use variables for inputs
* Define outputs
* Call module using `module` block

---

## 11. Difference between variables and locals?

* **Variables** → external inputs
* **Locals** → internal reusable values

---

## 12. What are input and output variables?

* **Input variables** → pass values into modules
* **Output variables** → expose values after execution

---

## 13. What is a backend in Terraform?

Backend defines where Terraform stores state (local or remote).

---

## 14. Difference between local and remote backend?

* **Local** → stored on local machine
* **Remote** → stored in S3, Terraform Cloud, etc.

---

## 15. What is state locking?

Prevents multiple users from modifying state simultaneously. Avoids corruption.

---

## 16. What is Terraform workspace?

Workspaces allow managing multiple environments (dev, prod) using same code.

---

## 17. How do you manage multiple environments?

* Workspaces
* Separate state files
* Separate folders/modules

---

## 18. What is dependency in Terraform?

Terraform automatically detects dependencies based on resource references.

---

## 19. What is `depends_on`?

Explicitly defines dependencies between resources.

---

## 20. What are provisioners?

Used to execute scripts during resource creation (e.g., `remote-exec`). Not recommended for heavy use.

---

## 21. Difference between `count` and `for_each`?

* **count** → index-based
* **for_each** → key/value-based (preferred for dynamic resources)

---

## 22. What is interpolation?

Used to reference variables/resources:

```hcl
${var.name}
```

---

## 23. How do you handle secrets in Terraform?

* Use environment variables
* Use secret managers (AWS Secrets Manager)
* Avoid hardcoding

---

## 24. Best practices for Terraform code?

* Use modules
* Use remote state
* Enable state locking
* Follow naming conventions
* Avoid hardcoding values

---

## 25. How do you optimize Terraform performance?

* Use targeted apply
* Reduce unnecessary resources
* Use proper state management
* Use parallelism

---

## 26. How do you handle state file corruption?

* Restore from backup
* Use versioning in S3
* Manually fix state (last resort)

---

## 27. What is drift in Terraform?

Drift occurs when infrastructure changes outside Terraform.

---

## 28. How do you handle drift?

* Run `terraform plan` regularly
* Use drift detection pipelines
* Re-apply configuration

---

## 29. How do you integrate Terraform with CI/CD?

* Use Jenkins/GitHub Actions
* Automate `init`, `plan`, `apply`
* Add approval steps for production

---

## 30. How do you import existing infrastructure?

```bash
terraform import <resource> <id>
```

---

## 31. How do you debug Terraform issues?

* Use `terraform plan`
* Enable logs:

```bash
TF_LOG=DEBUG
```

* Check state file
* Validate config:

```bash
terraform validate
```
